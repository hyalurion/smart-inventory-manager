## 构建脚本编译错误修正（Sync 阶段）
- 错误1：`alias(libs.plugins.hilt.android)` 报 Unresolved reference 'android'。版本目录里插件 key 是 `hilt`（非 `hilt.android`），插件访问器应为 `libs.plugins.hilt`。已修正。
- 错误2（用户指出）：原用 KAPT（`org.jetbrains.kotlin.kapt`）报 "plugin already on the classpath with an unknown version"——因为 kapt 由 Kotlin Gradle 插件随附提供，在 `plugins{}` 块里再用版本目录显式指定版本会冲突。且 Kotlin 2.x(K2)时代 KAPT 已弃用，正确做法是改用 **KSP**。已切换：
  - `libs.versions.toml`：[versions] 加 `ksp = "2.3.11"`；[plugins] 用 `ksp = { id = "com.google.devtools.ksp", version.ref = "ksp" }` 替换 `kotlin-kapt`。
  - `app/build.gradle.kts`：插件 `alias(libs.plugins.ksp)`；依赖 `ksp(libs.androidx.room.compiler)`、`ksp(libs.hilt.compiler)`。
- 关键事实：KSP 自 **2.3.0 起脱离 Kotlin 版本绑定**（独立版本线 KSP2），故 Kotlin 2.4.10 配 KSP `2.3.11`（最新稳定，2026-08-03）。旧 `<kotlin版本>-<ksp版本>` 前缀命名已废弃。不要用 `2.4.10-1.0.x` 去查 KSP。
- Hilt 2.60.1 / Room 2.8.4 均支持 KSP，标准 `ksp(...)` 配置即可，无需额外 sourceSet 配置。

## 修复"统计卡片正常、库存清单空白"（StateFlow 并发竞争）
- 根因：`InventoryScreen` 的 `LaunchedEffect(Unit)` 同时调 `loadInventory()` 与 `loadStatistics()`，二者各 `viewModelScope.launch` 并发跑在 `Dispatchers.IO` 不同线程；原 `InventoryViewModel` 对所有状态用 `_uiState.value = _uiState.value.copy(...)` 这种"先读后写"。当 `loadStatistics` 在 `loadInventory` 写入 `items` **之后**才把基于旧读（items 仍为空）算出的新值写回时，会**把 items 覆盖成空**。统计接口返回通常更快 → 稳定复现"统计有值、清单为空"。
- 修复：把 ViewModel 全部状态写入改为原子的 `_uiState.update { it.copy(...) }`（CAS 循环，两个并发修改会正确合并，不再互相覆盖）。新增 `import kotlinx.coroutines.flow.update`；`applyFilters()` 也改为在 `update` 内读最新 `items` 并写 `filteredItems`。
- 同时加固 `InventoryScreen.InventoryItemsList` 布局：非空分支 `LazyColumn` 与空态 `GlassContainer` 均加 `.weight(1f)`，使其占满 Column 剩余高度、可独立滚动（避免无高度约束时撑不开）。
- 注意：本环境无 Gradle，依赖用户实际构建/运行反馈验证；建议重新 Build 并在真机/模拟器确认清单有内容。

## 修复 Gson 多格式日期适配器导致的"清单空白"（编译 + 解析）
- 根因：后端 Go 日期序列化格式多样（`expiryDate`→`YYYY-MM-DD`，`createdAt` 等→`YYYY-MM-DDTHH:MM:SS`，可带毫秒/空格分隔）；原 Gson 用单一严格 `setDateFormat("...SSSSSS")` → 整包 `InventoryItemsResponse` 反序列化抛 `JsonSyntaxException` → 仓库 try/catch 静默回退空本地库 → 清单空白；统计接口全是 int 无日期故正常。网络其实 200（logcat "获取成功"）但被吞异常。
- 修复：`InventoryRepository.ApiFactory` 去掉 `setDateFormat`，改为 `GsonBuilder().registerTypeAdapter(Date::class.java, MultiFormatDateAdapter())`；`MultiFormatDateAdapter`（TypeAdapter<Date>）依次尝试 5 种格式，遇 null/空/不匹配返回 null，单条异常不拖垮整包。`InventoryViewModel.applyFilters()` 对 `name`/`description` 加 `.orEmpty()` 防 NPE。
- 编译修复：`MultiFormatDateAdapter` 用到的 `JsonToken` 须从 `com.google.gson.stream.JsonToken` 导入（不能写 `com.google.gson.JsonToken`）。已改正。

## 二次排查：清单仍空白（本轮真因 = Gson 日期格式严格匹配失败）
- 现象：Stats 卡片正常、清单空白，logcat 显示"从网络获取记录成功"。说明数据从后端拿到了，但 Android 端没显示。
- **真因**：`ApiFactory` 中 Retrofit 用的 Gson 原配 `setDateFormat("yyyy-MM-dd'T'HH:mm:ss.SSSSSS")`（单一、严格）。后端 Go 的 `model.Date/DateTime` 序列化实际输出为 `expiryDate -> "YYYY-MM-DD"`、`createdAt/updatedAt/lastUsedAt -> "YYYY-MM-DDTHH:MM:SS"`（无毫秒、无时区）。Gson 严格匹配不上 `.SSSSSS` → 抛 `JsonSyntaxException` → 整个 `InventoryItemsResponse` 反序列化失败 → `InventoryRepository.getAllItems()` 的 try/catch 静默回退到 `inventoryDao.getAll()`（首次本地库为空）→ 返回空列表。Stats 接口只含 int 字段、无日期 → 正常解析 → 卡片照常。
- **修复**：`InventoryRepository.kt` 去掉 `setDateFormat`，改为 `GsonBuilder().registerTypeAdapter(Date::class.java, MultiFormatDateAdapter())`；新增 `MultiFormatDateAdapter : TypeAdapter<Date?>`（依次尝试 `yyyy-MM-dd` / `yyyy-MM-dd'T'HH:mm:ss` / 含 .SSS/.SSSSSS / 空格分隔；null 或全失败返回 null，避免单条记录拖垮整包解析）。`id` 字段后端是 int、Android 是 String，Gson 的 String 适配器会按原始 token 读成 "123"，无需特别处理。
- 防御：`InventoryViewModel.applyFilters()` 中对 `item.name`/`item.description` 加 `.orEmpty()`，避免后端返回 null 时在搜索分支 NPE（默认 searchQuery 为空不会触发，搜索时才走）。
- 已知后续隐患（暂未改，避免范围蔓延）：`InventoryItem` 用 Gson 反射反序列化 Kotlin data class，后端未返回的字段（price/currency/metadata/tags/syncStatus 等）会以 JVM 默认值（null）填充，若后续代码访问非空的 `syncStatus` 等可能 NPE；如需健壮可改用 kotlinx.serialization 或给这些字段加默认值/可空化。
