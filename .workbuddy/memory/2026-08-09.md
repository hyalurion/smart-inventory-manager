## 构建脚本编译错误修正（Sync 阶段）
- 错误1：`alias(libs.plugins.hilt.android)` 报 Unresolved reference 'android'。版本目录里插件 key 是 `hilt`（非 `hilt.android`），插件访问器应为 `libs.plugins.hilt`。已修正。
- 错误2（用户指出）：原用 KAPT（`org.jetbrains.kotlin.kapt`）报 "plugin already on the classpath with an unknown version"——因为 kapt 由 Kotlin Gradle 插件随附提供，在 `plugins{}` 块里再用版本目录显式指定版本会冲突。且 Kotlin 2.x(K2)时代 KAPT 已弃用，正确做法是改用 **KSP**。已切换：
  - `libs.versions.toml`：[versions] 加 `ksp = "2.3.11"`；[plugins] 用 `ksp = { id = "com.google.devtools.ksp", version.ref = "ksp" }` 替换 `kotlin-kapt`。
  - `app/build.gradle.kts`：插件 `alias(libs.plugins.ksp)`；依赖 `ksp(libs.androidx.room.compiler)`、`ksp(libs.hilt.compiler)`。
- 关键事实：KSP 自 **2.3.0 起脱离 Kotlin 版本绑定**（独立版本线 KSP2），故 Kotlin 2.4.10 配 KSP `2.3.11`（最新稳定，2026-08-03）。旧 `<kotlin版本>-<ksp版本>` 前缀命名已废弃。不要用 `2.4.10-1.0.x` 去查 KSP。
- Hilt 2.60.1 / Room 2.8.4 均支持 KSP，标准 `ksp(...)` 配置即可，无需额外 sourceSet 配置。

## KSP 处理 Hilt 时报 HiltViewModel could not be resolved
- 三个 ViewModel 错误地把 `@HiltViewModel` 注解 import 成 `androidx.hilt.lifecycle.HiltViewModel`（不存在的包），KSP 的 InjectProcessingStep 因此无法解析注解类型而失败。
- 正确全限定名是 `dagger.hilt.android.lifecycle.HiltViewModel`（在 `hilt-android` 里）。不要和 `androidx.hilt.navigation.compose.hiltViewModel`（小写函数，用于 Composable 中获取 VM）的包混淆。
- 已统一改为 `import dagger.hilt.android.lifecycle.HiltViewModel`，三个 ViewModel 均已修正。

## compileReleaseKotlin 编译错误修正（KSP 已通过后）
- `MainActivity.kt` 同 `@HiltViewModel` 一样的坑：`@AndroidEntryPoint` 错 import 成 `androidx.hilt.android.AndroidEntryPoint`（不存在），应为 `dagger.hilt.android.AndroidEntryPoint`。已改。
- Nav3 `NavDisplay` 的 contentSelector **直接接收 NavKey（路由本身）**，不是带 `.key` 的包装。原代码写成 `{ entry -> when(val key = entry.key) }` 导致 `entry.key` Unresolved 且整体推断成 Unit。已改为 `{ key -> when(key){...} }` 并在末尾加 `else ->` 分支兜底（两个 when 都因 `NavKey` 为开放类型而需 else 才穷尽）。

- 潜在隐患已排除：`InventoryItem.id` 是 `String`，`Routes.Edit(item.id)` 类型匹配；`NavEntry(Routes.X)` 写法与官方 Nav3 样例一致（NavEntry 协变/构造器可接收子类型 key）。
